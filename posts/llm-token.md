# AI 大模型是如何计算 Token 的

> 和大模型打交道绕不开 "token" 这个词：计费按 token、上下文长度按 token、限流也按 token。这篇文章讲清楚它到底是什么、怎么算出来的。

## 一、Token 不是字，也不是词

大模型不能直接理解文字，它只能处理数字。所以文本送进模型前要先经过一个**分词器（Tokenizer）**，把文本切成一个个小单元，每个单元就是一个 **token**，再映射成数字编号。

关键认知：

- 1 token ≠ 1 个字符
- 1 token ≠ 1 个单词
- token 是介于"字符"和"词"之间的统计产物

一个英文单词通常是 1~2 个 token（`hello` → 1 个，`unbelievable` 可能切成 2~3 个）；一个汉字通常是 1~2 个 token。

## 二、主流方案：BPE 分词

现代大模型普遍使用 **字节对编码（Byte-Pair Encoding，BPE）** 或其变体（如 GPT 系列用的 byte-level BPE），基本思路是"高频搭配合并"：

1. 把文本拆成最小单位（字节或字符），建一个初始词表；
2. 统计语料库中**相邻单元对**的出现频率；
3. 把出现最频繁的一对合并成新单元，加入词表；
4. 重复第 2~3 步，直到词表达到预设大小（通常 5 万 ~ 20 万）。

训练完成后，常见词（如 `the`、`的`、`ing`）各自是一个 token，生僻词则被拆成多个碎片。例如：

```
"unhappiness" → ["un", "happi", "ness"]     （3 个 token）
"hello world" → ["hello", " world"]          （2 个 token）
```

**为什么英文省、中文费？** 因为 BPE 词表主要由英文语料训练而来，英文高频词天然占一个 token；中文要靠训练语料中"字/词组"的出现频率来合并，覆盖不足时就退化成按字甚至按字节切，一个汉字可能变成 2~3 个 token。近年来国产模型扩充了中文词表，中文 token 效率已明显改善。

## 三、tokenizer 是模型的一部分，不通用

同一段文本在不同模型下的 token 数**不一样**，因为每个模型的分词器和词表都是训练时定死的：

- OpenAI GPT 系列用 `tiktoken`，可通过官方接口精确计算
- Anthropic Claude、Google Gemini、各开源模型（Llama、Qwen 等）都有自己的分词器
- 同一个模型家族内分词器通常保持一致，但跨家族绝对不能混算

所以精确计数只能用对应模型官方的 tokenizer；跨模型比较时只能用"每 token 对应约 0.75 个英文单词、中文约 1~1.5 字/1 token"这类经验值估算。

## 四、token 数如何影响成本与上下文

**计费**是双向收费的：

```
费用 = 输入 token 数 × 输入单价 + 输出 token 数 × 输出单价
```

输出单价通常是输入的 3~5 倍——因为输出是逐个 token 生成的，每个 token 都要做一次完整的前向计算。

**上下文窗口**限制的是"输入 + 输出"的总 token 数。比如窗口 128K，你塞进去 120K 的资料，模型最多只剩 8K 空间给回答。超了会报错或触发截断（丢掉开头），所以长文档场景下"先精确数 token 再决定怎么切分"是刚需。

**推理成本**也和 token 数成正比：注意力计算的开销随序列长度增长，输出 1 万 token 的请求比输出 1 千 token 的请求又贵又慢，这不是计费策略，而是计算量的真实差异。

## 五、怎么估算和精确计算

**粗估经验值**：

| 语言 | 经验比例 |
| ---- | ---- |
| 英文 | 1 token ≈ 0.75 个单词，约 4 个字符 |
| 中文 | 1 token ≈ 1~1.5 个汉字（视模型词表） |
| 代码 | 符号多，1 行代码 ≈ 10~20 token |

**精确计算**：用官方分词器。以 OpenAI 的 Python 库为例：

```python
import tiktoken

enc = tiktoken.get_encoding("o200k_base")   # GPT-4o 系列的编码
tokens = enc.encode("大模型是如何计算 token 的")
print(len(tokens))        # token 数
print([enc.decode([t]) for t in tokens])   # 看每个 token 对应的文本
```

这段代码能看到分词的"真相"：哪些字被合并了、哪些被拆碎了，跑一遍比读十篇文章直观。

## 六、一个实用的推论

理解了 BPE，很多"玄学"就能解释了：

- 为什么模型数不清 `strawberry` 里有几个 r？——它看到的不是字母，是 token 编号
- 为什么中文 prompt 有时更贵？——词表覆盖率问题
- 为什么同一 prompt 换模型后 token 数变了？——分词器不同
- 为什么提示词要避免拼写错误？——错拼的词会被拆成罕见碎片，浪费 token 还可能被错误理解

一句话总结：**token 是分词器用统计方法切出来的"高频碎片"，它是模型世界的原子单位——一切计费、限制和成本，都从这次切分开始。**
